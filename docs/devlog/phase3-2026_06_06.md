## What I learned

### Minimap AABB overlay: the half-gap correction

When projecting game-world AABB coordinates onto the debug minimap, a `-1` offset is needed on both axes to keep the red rect centred inside the correct tile.

**Why it arises**

The minimap draws each tile as a `MINI_TILE × MINI_TILE` (12 × 12 px) square, with tiles spaced at a stride of `MINI_TILE + PADDING = 14 px`. The 2 px of padding is trailing dead space after each tile:

```
tile 0 drawn:  [0 … 11]  gap: [12, 13]
tile 1 drawn: [14 … 25]  gap: [26, 27]
```

The scale factor used to project game pixels to minimap pixels is:

```cpp
constexpr float SCALE = (MINI_TILE + PADDING) / static_cast<float>(TILE_SIZE);
// = 14 / 24
```

This maps 1 game pixel to one *stride unit*, not one *drawn pixel*. It correctly places tile left-edges (`col * TILE_SIZE * SCALE = col * 14`), but it also distributes the padding evenly across each tile's budget.

**The discrepancy**

The visual centre of minimap tile 0 is at `MINI_TILE / 2 = 6 px`.  
The centre of game tile 0 (game pixel `TILE_SIZE / 2 = 12`) maps under SCALE to `12 × (14/24) = 7 px`.

The gap is `PADDING / 2 = 1 px`. SCALE stretches the game tile across a 14-px stride, but the drawn tile only occupies the left 12 px — so its visual midpoint sits 1 px to the left of the stride midpoint.

**The fix**

Subtracting `PADDING / 2 = 1` from every scaled coordinate shifts the AABB back into alignment:

```
game tile 0 centre (px 12)  →  12 × (14/24) − 1 = 6  ✓  (= MINI_TILE / 2)
game tile 1 centre (px 36)  →  36 × (14/24) − 1 = 20 ✓  (= 14 + 6)
```

In code (`debug.cpp`):

```cpp
constexpr float SCALE = (MINI_TILE + PADDING) / static_cast<float>(TILE_SIZE);
ImVec2 tl{
    origin.x + pacman.bounds.x * SCALE - 1,          // -1 = PADDING / 2
    origin.y + pacman.bounds.y * SCALE - 1
};
ImVec2 br{
    origin.x + (pacman.bounds.x + pacman.bounds.width)  * SCALE - 1,
    origin.y + (pacman.bounds.y + pacman.bounds.height) * SCALE - 1
};
```

**General rule:** whenever SCALE encodes a stride (tile + gap) rather than the visible tile size alone, subtract `PADDING / 2` after scaling to realign with the visual tile centres. The same correction will apply to ghost AABB overlays.
